# Paso 14 — Prueba E2E de la Fase 0: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un comando (`tool/e2e.sh` en SUNO_client) que demuestra de punta a punta que una visita creada en modo avión en el emulador llega al servidor al reconectar.

**Architecture:** El script levanta un stack de producción efímero de SUNO_server con Docker (`localfs`, Caddy con CA interna para `10.0.2.2`), siembra una organización y un usuario únicos, y lanza una prueba `integration_test` en el emulador. La prueba y el script se coordinan con marcas en `adb logcat`: el script activa y desactiva el modo avión, y al final verifica la visita en la base de datos del servidor.

**Tech Stack:** Bash (Git Bash en Windows), Docker Compose, Caddy 2, Django `manage.py shell`, Flutter 3.44.9 `integration_test`, `adb`.

**Spec:** [2026-10-29-paso-14-e2e-design.md](2026-10-29-paso-14-e2e-design.md)

**Requisitos de la máquina:** Docker Desktop en marcha; Flutter 3.44.9 y Android SDK en el PATH; emulador `suno_api36` arrancado (`emulator -avd suno_api36`); `openssl` en el PATH (en Windows, `C:\Program Files\Git\usr\bin`).

**Ramas:** SUNO_server `feat/e2e-infra` (Tareas 1–3 y 8), SUNO_client `feat/e2e-fase0` (Tareas 4–7). Un PR por repo; el de SUNO_server primero.

```markdown
# Prueba E2E de la Fase 0

Demuestra el criterio de salida de la Fase 0 (doc 08 §8): una visita creada
**en modo avión** en un emulador Android llega al servidor al reconectar.
Cierra el Paso 14 del plan de construcción.

## Requisitos

- Docker Desktop en marcha.
- Flutter 3.44.9 y Android SDK en el PATH; `openssl` en el PATH (Windows:
  `C:\Program Files\Git\usr\bin`).
- Un emulador Android arrancado (`emulator -avd suno_api36`).
- SUNO_server y SUNO_client clonados uno al lado del otro.

## Ejecutar

Desde SUNO_client:

    bash tool/e2e.sh

Opciones por variable: `SUNO_SERVER_DIR` (por defecto `../SUNO_server`),
`ANDROID_SERIAL` (si hay más de un dispositivo).

**Borra los datos de la app en el emulador** (`pm clear`): sesión, visitas

## Qué hace

1. Genera `infra/.env.e2e` con secretos de un solo uso
   (`infra/scripts/ci_dast_env.sh`, settings de producción, `localfs`).
2. Levanta `db`, `api` y `caddy` en el proyecto de compose `suno-e2e`.
   Caddy firma `10.0.2.2` con su CA interna y lo sirve también sin SNI
   (`default_sni`).

4. Lanza `integration_test/e2e_fase0_test.dart`, que:
   acepta el aviso de privacidad, hace login, **acepta el certificado

6. Siempre, también si falla: desactiva el modo avión y hace `down -v`.

El script y la prueba se coordinan por marcas en `adb logcat`:
`E2E:READY_FOR_OFFLINE`, `E2E:SAVED_OFFLINE`, `E2E:SYNCED`.

## Fuera de alcance

Fotos y adjuntos (Paso 18; necesitan un S3 local, issue #21), iOS y CI.
```

### Task 5: La prueba de integración (SUNO_client)

**Files:**
- Create: `integration_test/e2e_fase0_test.dart`

- [ ] **Step 1: Escribir la prueba**

```dart
// Prueba E2E de la Fase 0 (Paso 14). La ejecuta `tool/e2e.sh`, que levanta
// el servidor, controla el modo avión y verifica el resultado en el servidor.
// No funciona sola: necesita los --dart-define que pasa el script.
//
// Coordinación con el script por `adb logcat` (tag `flutter`):
//   E2E:READY_FOR_OFFLINE  → el script activa el modo avión
//   E2E:SAVED_OFFLINE      → el script lo desactiva
//   E2E:SYNCED             → el script verifica en el servidor
import 'dart:io';

import 'package:flutter/material.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:integration_test/integration_test.dart';
import 'package:visitacampo/features/home/visit_status_list.dart';
import 'package:visitacampo/main.dart' as app;

const _username = String.fromEnvironment('E2E_USERNAME');
const _password = String.fromEnvironment('E2E_PASSWORD');
const _marker = String.fromEnvironment('E2E_MARKER');
const _host = String.fromEnvironment('E2E_HOST', defaultValue: '10.0.2.2');

void main() {
  IntegrationTestWidgetsFlutterBinding.ensureInitialized();

  testWidgets('una visita creada en modo avión llega al servidor al reconectar', (tester) async {
    expect(_username.isNotEmpty && _password.isNotEmpty && _marker.isNotEmpty, isTrue,
        reason: 'Ejecutar con tool/e2e.sh: faltan E2E_USERNAME/E2E_PASSWORD/E2E_MARKER');

    await app.main();
    await _pumpUntilAny(tester, [
      find.byKey(const Key('privacy_accept_button')),
      find.byKey(const Key('login_submit_button')),
    ]);

    // Aviso de privacidad (Ley 1581), solo si falta la autorización.
    if (find.byKey(const Key('privacy_accept_button')).evaluate().isNotEmpty) {
      for (final purpose in ['account', 'location', 'photos']) {
        await tester.tap(find.byKey(Key('privacy_$purpose')));
        await tester.pump();
      }
      await tester.tap(find.byKey(const Key('privacy_accept_button')));
      await _pumpUntil(tester, find.byKey(const Key('login_submit_button')));
    }

    // Login. El primer intento choca con la CA interna de Caddy: TOFU.
    await tester.enterText(find.byKey(const Key('login_username_field')), _username);
    await tester.enterText(find.byKey(const Key('login_password_field')), _password);
    await tester.tap(find.byKey(const Key('login_submit_button')));
    await _pumpUntil(tester, find.byKey(const Key('tofu_trust_button')));
    await tester.tap(find.byKey(const Key('tofu_compared_check')));
    await tester.pump();
    await tester.tap(find.byKey(const Key('tofu_trust_button')));
    await _pumpUntil(tester, find.byKey(const Key('home_new_visit_button')), timeout: const Duration(seconds: 60));

    // Sincronización inicial: trae la plantilla publicada.
    await tester.tap(find.byKey(const Key('home_sync_button')));
    await _pumpUntil(tester, find.byKey(const Key('home_last_sync')), timeout: const Duration(seconds: 60));

    // Sin red.
    _mark('READY_FOR_OFFLINE');
    await _waitUntilOffline(tester);

    // Captura offline.
    await tester.tap(find.byKey(const Key('home_new_visit_button')));
    await _pumpUntil(tester, find.byKey(const Key('capture_save_button')));
    final notas = find.descendant(
      of: find.byKey(const ValueKey('form-field-notas')),
      matching: find.byType(TextField),
    );
    await tester.enterText(notas, _marker);
    await tester.tap(find.byKey(const Key('capture_save_button')));
    await _pumpUntil(tester, find.byKey(const Key('home_new_visit_button')));
    await _pumpUntil(tester, _chip('Pendiente'));
    _mark('SAVED_OFFLINE');

    // Con red: sincroniza hasta que la visita quede confirmada.
    final deadline = DateTime.now().add(const Duration(seconds: 120));
    while (_chip('Sincronizada').evaluate().isEmpty) {
      if (DateTime.now().isAfter(deadline)) fail('La visita no pasó a Sincronizada en 120 s');
      await tester.tap(find.byKey(const Key('home_sync_button')));
      await _pumpFor(tester, const Duration(seconds: 10));
    }
    _mark('SYNCED');
  });
}

Finder _chip(String label) =>
    find.descendant(of: find.byType(VisitStatusChip), matching: find.text(label));

void _mark(String name) {
  // ignore: avoid_print
  print('E2E:$name');
}

/// La propia prueba comprueba que el modo avión ya está activo: ningún
/// paquete llega al host.
Future<void> _waitUntilOffline(WidgetTester tester) async {
  final deadline = DateTime.now().add(const Duration(seconds: 60));
  while (true) {
    try {
      final socket = await tester.runAsync(
        () => Socket.connect(_host, 443, timeout: const Duration(seconds: 2)),
      );
      socket?.destroy();
    } on SocketException {
      return;
    }
    if (DateTime.now().isAfter(deadline)) fail('El host seguía accesible tras 60 s: ¿modo avión?');
    await _pumpFor(tester, const Duration(seconds: 1));
  }
}

/// `pumpAndSettle` no sirve: los temporizadores de sincronización y las
/// animaciones de carga nunca dejan la app quieta.
Future<void> _pumpUntil(WidgetTester tester, Finder finder,
    {Duration timeout = const Duration(seconds: 30)}) =>
    _pumpUntilAny(tester, [finder], timeout: timeout);

Future<void> _pumpUntilAny(WidgetTester tester, List<Finder> finders,
    {Duration timeout = const Duration(seconds: 30)}) async {
  final deadline = DateTime.now().add(timeout);
  while (!finders.any((f) => f.evaluate().isNotEmpty)) {
    if (DateTime.now().isAfter(deadline)) fail('No apareció ninguno de $finders en $timeout');
    await tester.pump(const Duration(milliseconds: 200));
  }
}

Future<void> _pumpFor(WidgetTester tester, Duration duration) async {
  final end = DateTime.now().add(duration);
  while (DateTime.now().isBefore(end)) {
    await tester.pump(const Duration(milliseconds: 200));
  }
}
```

### Task 6: El orquestador (SUNO_client)

**Files:**
- Create: `tool/e2e.sh`

- [ ] **Step 1: Escribir el script**

```bash
#!/usr/bin/env bash
# Prueba E2E de la Fase 0 (Paso 14): una visita creada en modo avión en el
# emulador llega al servidor al reconectar. Procedimiento completo en
# SUNO_server docs/testing/e2e-fase0.md.
#
# Uso: bash tool/e2e.sh
#   SUNO_SERVER_DIR  checkout de SUNO_server (por defecto ../SUNO_server)
#   ANDROID_SERIAL   dispositivo, si hay más de uno conectado
#
# Borra los datos de la app en el emulador (pm clear).
set -euo pipefail

CLIENT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
SERVER_DIR="$(cd "${SUNO_SERVER_DIR:-$CLIENT_DIR/../SUNO_server}" && pwd)"
PACKAGE=com.visitacampo.visitacampo
HOST=10.0.2.2
RUN_ID="e2e-$(date +%Y%m%d%H%M%S)"
ENV_FILE="$SERVER_DIR/infra/.env.e2e"
WORK="$(mktemp -d)"
COMPOSE=(docker compose -p suno-e2e --project-directory "$SERVER_DIR/infra"
  --env-file "$ENV_FILE" -f "$SERVER_DIR/infra/docker-compose.yml")

log() { printf '\n[e2e] %s\n' "$*"; }
die() { printf '\n[e2e] ERROR: %s\n' "$*" >&2; exit 1; }

cleanup() {
  local status=$?
  set +e
  adb shell cmd connectivity airplane-mode disable >/dev/null 2>&1
  [[ -n "${LOGCAT_PID:-}" ]] && kill "$LOGCAT_PID" 2>/dev/null
  [[ -n "${TEST_PID:-}" ]] && kill "$TEST_PID" 2>/dev/null
  if [[ $status -ne 0 && -f "$ENV_FILE" ]]; then
    log "Últimas líneas del servidor:"
    "${COMPOSE[@]}" logs --tail 40 api caddy
  fi
  [[ -f "$ENV_FILE" ]] && "${COMPOSE[@]}" down -v >/dev/null 2>&1
  rm -f "$ENV_FILE"
  rm -rf "$WORK"
  [[ $status -eq 0 ]] && log "OK: la visita $RUN_ID llegó al servidor." || log "FALLÓ (código $status)."
}
trap cleanup EXIT

# --- Preflight ---------------------------------------------------------------
command -v docker >/dev/null || die "Falta docker."
docker info >/dev/null 2>&1 || die "Docker no responde: abre Docker Desktop."
command -v flutter >/dev/null || die "Falta flutter en el PATH."
command -v adb >/dev/null || die "Falta adb en el PATH (Android SDK platform-tools)."
command -v openssl >/dev/null || die "Falta openssl (Windows: añade C:\\Program Files\\Git\\usr\\bin al PATH)."
[[ -f "$SERVER_DIR/infra/docker-compose.yml" ]] || die "No encuentro SUNO_server en $SERVER_DIR (usa SUNO_SERVER_DIR)."
adb get-state >/dev/null 2>&1 || die "No hay emulador conectado: emulator -avd suno_api36"

# --- Servidor ----------------------------------------------------------------
log "Generando $ENV_FILE"
PASSWORD="$(ENV_FILE="$ENV_FILE" DAST_HOST="$HOST" bash "$SERVER_DIR/infra/scripts/ci_dast_env.sh")"

log "Levantando db, api y caddy (suno-e2e)"
"${COMPOSE[@]}" up -d --build db api caddy

log "Esperando a la API"
for _ in $(seq 1 60); do
  if "${COMPOSE[@]}" exec -T caddy cat /data/caddy/pki/authorities/local/root.crt >"$WORK/root.crt" 2>/dev/null &&
     curl -sf --cacert "$WORK/root.crt" --connect-to "$HOST:443:127.0.0.1:443" "https://$HOST/v1/healthz" >/dev/null; then
    break
  fi
  sleep 2
done
curl -sf --cacert "$WORK/root.crt" --connect-to "$HOST:443:127.0.0.1:443" "https://$HOST/v1/healthz" >/dev/null ||
  die "La API no respondió en https://$HOST/v1/healthz en 120 s."

log "Sembrando organización y usuario $RUN_ID"
"${COMPOSE[@]}" exec -T api python manage.py bootstrap_demo \
  --org-name "E2E $RUN_ID" --username "$RUN_ID" --password "$PASSWORD" >/dev/null

# --- App -----------------------------------------------------------------------
log "Limpiando los datos de la app en el emulador"
adb shell pm clear "$PACKAGE" >/dev/null 2>&1 || true
adb shell cmd connectivity airplane-mode disable >/dev/null
adb logcat -c

log "Lanzando la prueba de integración"
(
  cd "$CLIENT_DIR"
  flutter test integration_test/e2e_fase0_test.dart \
    --dart-define=VISITACAMPO_API_BASE_URL="https://$HOST" \
    --dart-define=E2E_HOST="$HOST" \
    --dart-define=E2E_USERNAME="$RUN_ID" \
    --dart-define=E2E_PASSWORD="$PASSWORD" \
    --dart-define=E2E_MARKER="$RUN_ID"
) >"$WORK/flutter.log" 2>&1 &
TEST_PID=$!

# El modo avión lo controla el script, a la señal de la prueba.
adb logcat -s flutter:I >"$WORK/logcat.log" 2>/dev/null &
LOGCAT_PID=$!
offline=0
while kill -0 "$TEST_PID" 2>/dev/null; do
  if [[ $offline -eq 0 ]] && grep -q 'E2E:READY_FOR_OFFLINE' "$WORK/logcat.log"; then
    log "Modo avión: ON"
    adb shell cmd connectivity airplane-mode enable >/dev/null
    offline=1
  fi
  if [[ $offline -eq 1 ]] && grep -q 'E2E:SAVED_OFFLINE' "$WORK/logcat.log"; then
    log "Modo avión: OFF"
    adb shell cmd connectivity airplane-mode disable >/dev/null
    offline=2
  fi
  sleep 1
done
TEST_STATUS=0
wait "$TEST_PID" || TEST_STATUS=$?
TEST_PID=
tail -n 25 "$WORK/flutter.log"
[[ $TEST_STATUS -eq 0 ]] || die "La prueba de integración falló (log completo arriba)."
grep -q 'E2E:SYNCED' "$WORK/logcat.log" || die "La prueba terminó sin la marca E2E:SYNCED."

# --- Verificación en el servidor ---------------------------------------------
log "Verificando la visita en el servidor"
"${COMPOSE[@]}" exec -T -e E2E_MARKER="$RUN_ID" api python manage.py shell -c '
```
